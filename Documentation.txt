# TASK TRACKER CLI — PROJECT SPECIFICATION

## 1. Project Purpose

This is a Roadmap.sh Task Tracker CLI project.

The project has two purposes:

1. Complete the Roadmap.sh Task Tracker requirements.
2. Produce a clean and professional GitHub portfolio project while gaining practical experience with C#, .NET, CLI applications, file handling, JSON persistence, basic architecture, and Git/GitHub workflow.

This is not intended to become a long-term or large-scale application.

The project should be completed efficiently and should not become an unnecessary learning detour from the user's main .NET Backend course.

---

## 2. Primary Goal

The Roadmap.sh requirements are the project's primary acceptance criteria.

The implementation must satisfy the specified functionality and constraints from the Roadmap.sh Task Tracker project.

Do not add unrelated features unless explicitly requested.

---

## 3. Roadmap.sh Requirements

The application must:

- Run from the command line.
- Accept actions and inputs as command-line arguments.
- Store tasks in a JSON file.
- Create the JSON file if it does not exist.
- Use the native file system capabilities of the chosen programming language.
- Avoid external libraries or frameworks for building the project.
- Handle errors and edge cases carefully.

The user must be able to:

- Add a task.
- Update a task.
- Delete a task.
- Mark a task as in progress.
- Mark a task as done.
- List all tasks.
- List tasks that are done.
- List tasks that are not done.
- List tasks that are in progress.

---

## 4. Task Properties

Each task should contain:

- id — unique identifier
- description — short description of the task
- status — todo, in-progress, or done
- createdAt — date and time when the task was created
- updatedAt — date and time when the task was last updated

The JSON file must be updated when a task is added or updated.

---

## 5. Roadmap.sh Constraints

The project should follow these constraints:

- Command-line interface.
- Positional command-line arguments.
- JSON file persistence.
- JSON file located in the current directory.
- JSON file automatically created if it does not exist.
- Native file-system capabilities.
- No external libraries or frameworks for the core project.
- Errors and edge cases should be handled.

The project should remain simple and focused.

---

## 6. Technology Stack

Current stack:

- C#
- .NET 10
- Console Application
- Visual Studio Code
- Git
- GitHub
- JSON file for persistence

Database is NOT part of this project.

Do not introduce SQL Server, SQLite, Entity Framework, or another database.

The purpose of this project is to become comfortable with file-based persistence and JSON handling.

## 11. Learning Workflow

The project should follow a guided implementation approach.

For each important task:

1. Explain the relevant concept briefly.
2. Explain what needs to be achieved.
3. Let the user attempt the implementation.
4. Review the implementation.
5. Correct misunderstandings.
6. Confirm that the user understands the important part.
7. Move to the next task.

Do not repeatedly ask the user the same questions.

Do not assign many tasks at once.

Do not block progress on minor details.

If the user does not understand a fundamental concept required for the current step, explain that concept before moving forward.

The project is considered complete only when:

- all Roadmap.sh requirements are implemented;
- important edge cases are handled;
- architecture/design has been reviewed;
- code is clean and understandable;
- unnecessary files are removed from the repository;
